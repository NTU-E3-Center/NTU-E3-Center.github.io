Executive Summary

Update — 2026-07-03: 12 of the 59 findings are now resolved (all 3 fix-first items, both latent build-crash paths, and 7 secondary cleanups). See Remediation Status. The assessment below reflects the original audit state.

This is a healthy, well-structured custom static-site generator: adversarial verification of every candidate found no critical or high-severity defects—all 59 confirmed findings are medium (7) or low (52), and the profile is dominated by maintainability/DRY debt rather than correctness, security, or availability bugs. The few items worth prioritizing are two latent build-crash paths (an int-vs-string year and a missing beautifulsoup4 in the README's install line), one WCAG keyboard-access gap in the media lightbox, and repo-hygiene bloat (110 MB of unreferenced PDFs and un-LFS'd binaries pushing .git to ~426 MB). Everything else is copy-paste duplication, magic constants, and documentation drift that a small academic-lab team can burn down incrementally with low risk.

Critical Fixes

No critical or high-severity findings survived verification. The site builds, deploys, and renders correctly. The three items below are the medium-severity findings that can actually break a build or a user-facing feature—treat them as fix-first. A short list of additional latent crash paths (all low) follows.
Medium ✓ Resolved

Publication year is str/int contradictory; member-page sort crashes on an int year

build.py:424, 440
What breaks
README.md:101 documents "year": 2025 (int), but CLAUDE.md and all 57 entries store "'YY" strings. get_pub_sort_key normalizes; the member-page sort reads item.get('year', 0) and sorts on the raw (x['year'], x['month']) tuple. A contributor copying the README verbatim adds an int year—if that paper lists an E3 member, the member-page sort mixes int and str and raises TypeError at build time (blocks the deploy; no broken site is served).
Fix
Route the member sort through get_pub_sort_key (single source of truth), drop the 0 int default, and correct README.md:101 to "year": "'25".
Medium ✓ Resolved

README's pip list omits beautifulsoup4 — a fresh local build crashes

README.md:39
What breaks
README:39 says pip install markdown Pillow jinja2 openpyxl, but build.py:821 imports from bs4 import BeautifulSoup inside validate_seo() (called unconditionally at build.py:1068). A new contributor's build runs to "Validating SEO..." then dies with ModuleNotFoundError: No module named 'bs4'. (markupsafe is a jinja2 transitive dep and is not actually missing.)
Fix
Replace README:39 with pip install -r requirements.txt and delete the hand-maintained package list (requirements.txt already claims to be the single source of truth).
Medium ✓ Resolved

Zoomable media lightbox is mouse-only — no keyboard access (WCAG 2.1.1 A)

static/js/script.js:428
What breaks
The .zoomable tiles are plain <div>s with only a click handler—no tabindex, role, or keydown. Keyboard/switch users cannot open group-life photos or, critically, play the Featured Videos YouTube embed (the modal is the only playback path). (Evidence note: templates/home/group-life.html:60 is the homepage slider, not a lightbox tile; the real tiles are templates/pages/group-life.html:60 and templates/home/videos.html:49/58.)
Fix
Render tiles as <button> (or add tabindex="0" + role="button") and a keydown handler for Enter/Space that runs the same open logic; the modal already restores focus to the opener.
✓ Resolved 2026-07-03 — additional latent crash / build-integrity paths: malformed project.json now warns-and-skips with the offending path instead of aborting (build.py:621); a JSON null on a member str-leaf is now treated as an absent optional key (validate_member.py); and the member-page sort now routes through get_pub_sort_key (single source of truth) instead of the type-fragile inline month/year parser.

1Architecture & Folder Structure

Medium

110 MB of publication PDFs tracked but never referenced or built

contents/publications/files/Effort: small
Evidence
~110 MB across 24 PDFs; grep -c "files/" publications.json = 0; build.py never copies the folder; undocumented in STRUCTURE.md/README.
Impact
Dead weight inflating the working tree (~258 MB) and .git (~426 MB); slower clones/checkouts. No functional or deploy impact, and size is well within GitHub's comfort zone.
Fix
git rm the folder (or move to a Release asset / shared drive); if PDF downloads are wanted, add a file field to publications.json + a copy step. History purge (filter-repo/BFG) is optional and destructive.
Low

Internal SEO/analytics artifacts & design docs sit top-level, mixed with build inputs

SEO/, DESIGN_RULES/Effort: medium
Evidence
SEO/ (~412 KB of GA4/GSC CSVs, xlsx, zips, a seo-report.html, analysis markdown) and DESIGN_RULES/ live at repo root; neither is read by build.py.
Impact
Top level no longer cleanly signals what the SSG consumes. (Both are already documented in STRUCTURE.md/README, so the boundary is partly signposted; seo-report.html is a hand-curated deliverable, not a regenerable build product—do not gitignore it.)
Fix
Group non-build operational material under one top-level namespace (e.g. ops/ containing SEO/ and DESIGN_RULES/).

Medium

year format is doc-vs-data contradictory; two sort paths parse it inconsistently (member sort crashes on int)

build.py:424, 440Effort: small
Evidence
README:101 shows int 2025; CLAUDE.md + all 57 entries use string "'YY". get_pub_sort_key normalizes to int(20YY); the member path sorts on the raw string. Mixing an int year with existing string years raises TypeError.

Fix
Pick one canonical type: keep "'YY", fix README:101, and reuse get_pub_sort_key in the member sort. (See Critical Fixes.)
Overlaps with the two Code-Quality sort findings below (same root cause).

lib/excel_to_content.py:132Effort: small

Medium

Zoomable media lightbox is mouse-only — no keyboard access

static/js/script.js:428Effort: medium
Evidence
Only a click listener; .zoomable tiles are plain <div>s with no tabindex/role/keydown (templates/pages/group-life.html:60, templates/home/videos.html:49/58).
Impact
Keyboard/switch users cannot open group-life photos or play the Featured Videos embed—WCAG 2.1.1 (Level A) failure. Real functional loss for that widget.

Low

Image conversion regenerates every WebP variant on every build (no caching)

build.py:1009Effort: medium
Evidence

Impact
Build-time only; correct output always produced. Slows local iteration and wastes CI CPU.
Fix
Skip when all {basename}-{size}w.webp exist and are newer than the source; also invalidate the cache when sizes, quality, or target_aspect change in code.
Low

O(members × publications) author matching; publication list walked several times

build.py:418Effort: small
Evidence
The author match scans all pub sections inside the per-member loop (and re-parses month strings per member); pub_by_id is built twice; home/abstract/sitemap re-walk the list.
Impact
~2,300 trivial iterations, sub-10 ms, dominated by template rendering—no measurable impact.
Fix
Build one webid → sorted citationIds index (and one shared pub_by_id) in a single pass; reuse in project pages and the sitemap.
Low

Duplicated, divergent, type-fragile publication sort inside render_member_pages

build.py:424–440Effort: small
Evidence
Inline sort on raw string year vs the normalized get_pub_sort_key; months list copy-pasted L59→L427; int-0 default; month.lower() would raise on a null month.
Impact
Order is identical to the canonical path today; TypeError/AttributeError paths are latent (require data violating the repo conventions).
Fix
Delete the inline sort/month loop, reuse get_pub_sort_key, guard month with (item.get('month') or '') (also in get_pub_sort_key), and hoist the months list to a module constant.
Low

render_project_pages parses project.json with no error handling

build.py:621Effort: small
Evidence
Bare json.load, no try/except; a malformed file aborts the build with a raw JSONDecodeError whose path is only implicit in the traceback.
Impact
Both member and project pipelines already hard-fail on bad JSON; the real gap is message clarity (members print a clean path + line/col).
Fix
Catch JSONDecodeError, print a targeted message with detail_path + line/col, and SystemExit (mirroring members)—not a silent skip.
Low

Sitemap lastmod computation does redundant walks and repeated stats

build.py:743Effort: medium
Evidence

Impact
A few hundred cheap, inode-cached syscalls—single-digit ms on a 223-file tree.

Compute each shared mtime once (e.g. pubs_json_mtime) and memoize the dir-walk by path.
Low

Medium

Photo-discovery convention triplicated; find_image() returns a path the build never emits

lib/excel_to_content.py:151Effort: medium
Evidence
The same glob (stem =='photo', ext jpg/jpeg/png) is copy-pasted in find_image, build.py:1036–1041, and validate_member.py:251–252. find_image returns /assets/members/{webId}{sourceExt}, but only {webId}-Nw.webp is emitted—so the returned path is a dangling reference surviving only as the never-fetched <img src> fallback.

Medium

contents/videos/2025-1.mp4Effort: medium
Evidence

Architecture & Content Grouping Recommendations

The architecture findings converge on one theme: the repo root and contents/ no longer cleanly separate what the SSG consumes from operational/archival material and heavy binaries. None of this is broken—the build ignores the extra material—but tightening the boundary reduces clone size, onboarding confusion, and history bloat. Concrete moves:

  1. Purge or wire up the 110 MB PDF archive (contents/publications/files/). Either git rm it (and move the archive to a Release asset / shared drive), or, if downloads are a real feature, add a file field to publications.json plus a copy step. Nothing currently references it.
  2. Move large source binaries to Git LFS (or externalize video to YouTube). Add a .gitattributes for *.mp4 and source-resolution photos so future revisions don't accrete into history. A one-time filter-repo/BFG purge (destructive) reclaims the existing ~426 MB if size matters.
  3. Quarantine non-build material under a single ops/ namespace so the top level advertises only build inputs: relocate SEO/ and DESIGN_RULES/ there. Keep the hand-curated seo-report.html tracked (it has no generator); drop redundant zip-vs-CSV duplication.
  4. Introduce a config module + PROJECT_ROOT to kill the domain (~90 copies), output_dir, image-tier, and quality magic values, and to make paths CWD-independent.
  5. Remove tracked cruft: the duplicate e3-logo-icon 2.svg and the read-only member-info.legacy.xlsx (recoverable from history).
