Executive Summary

This is a mature, well-built responsive front end: it ships a :root design-token system with per-breakpoint overrides, a global overflow-wrap: break-word, a defensive html,body { overflow-x: clip } guard, and :focus-visible rings on most components. Adversarial verification of 22 candidate issues confirmed 18 and rejected 4 as already-handled or non-manifesting. The profile is dominated by touch-target and keyboard-accessibility gaps rather than broken layouts — only two genuine layout bugs survived (a status badge that overlaps publication titles below 1024px, and a mobile photo grid that renders one column where two were intended). Breakpoint note: the smallest media query is 37.5rem (600px), so the client's 320–375px target range is governed entirely by the ≤600px blocks, where the root also shrinks to 14px via html{font-size:87.5%} — this is what pushes several rem-based touch targets below the 44px minimum.

🚨 Critical RWD / UI Bugs

Items causing broken layouts, overflowing boxes, or content collision.

Fix-first. C1 collides a badge with real publication titles on every phone and tablet; C2 wastes half the gallery width on every phone. Both are small, self-contained CSS edits.
Critical

C1Publications list — “Manuscript” status badge overflows its date track and collides with the title

subpage.css:925, 784
Issue
On the ~10 working-status rows (Submitted / Under Review / Accepted) the date column holds an all-caps “MANUSCRIPT” pill instead of a month/year. Its box (≈90px) is wider than the row's fixed first grid track — 4rem (64px) at ≤1024px, 3rem (≈42px) at ≤600px — so the pill spills right and overlaps the publication title.
Screens
320–1024px (worst at 320–375px)
Why
.news-row uses a fixed first track (grid-template-columns: 3rem 1fr), not auto/minmax, so it never grows; .pub-status-badge is width: fit-content with letter-spacing:0.1em; text-transform:uppercase on a single unbreakable word, and neither .news-row nor .news-row-date has an overflow guard.
Fix
Let the first track size to the pill only when a badge is present (published rows keep their date-sized track): 
@media (max-width: 64rem) {
  .news-row:has(.pub-status-badge) { grid-template-columns: auto minmax(0,1fr) auto; }
}
@media (max-width: 37.5rem) {
  .news-row:has(.pub-status-badge) { grid-template-columns: auto minmax(0,1fr); }
  .news-row:has(.pub-status-badge):has(.pub-row-publisher) {
    grid-template-columns: auto minmax(0,1fr) auto;
  }
  .pub-status-badge { letter-spacing: 0.05em; } /* optional: relax crowding */
}
Medium

C2Featured Videos & Group Life photo grids collapse to 1 column on mobile (intended 2-up)

style.css:2662
Issue
The mobile override intends two thumbnails per row (its own comment: “Two-up at narrower widths”), but the column-width formula under-budgets the horizontal chrome, so auto-fill only ever fits one column — a single centered thumbnail flanked by large empty gutters — across the whole range. Affects both the homepage Featured-Videos gallery and the Group-Life “all” grid (shared CSS).
Screens
320–600px
Why
--_img-width: calc((100vw - 3rem)/2 - 0.5rem) assumes 3rem of chrome, but the section gutter is 2×2rem = 4rem and the formula ignores the column gap + per-column borders. Two tracks + gap total 100vw−2.5rem, which exceeds the available 100vw−4rem at every width, so the second column never fits. (Don't just delete --_img-width — it also drives the explicit .glf-img block width.)
Fix
Budget the real gutter + gap + borders so two tracks fit (w ≤ 50vw − 2.75rem): 
.glf-section[which='all'] {
  --_img-width: calc((100vw - 5rem) / 2 - 0.375rem); /* = 50vw - 2.875rem */
  gap: var(--space-4) var(--space-3);
  justify-content: center;
}

🎨 UI & Design Consistency Gaps

Items where the UI deviates from the design system or shows layout friction.

MediumConsistency

U1Contact form — input & textarea text renders slanted −3°

contact.html:93, 99, 107, 113 · general.css:769
Issue
The Name/Email/Subject inputs and the Message textarea carry class="skewed-block", applying skewX(-3deg). Every other skewed block keeps its text upright via .skewed-block > * { transform: skewX(+3deg) } — but native form controls have no element children, so nothing un-skews their placeholder/typed text. All field text renders tilted while labels stay upright, reading as a rendering glitch.
Screens
all widths
Fix
Opt the controls out of the skew (keeps the border/shadow frame) — one line in the existing .contact-field { & input, & textarea } rule (subpage.css): 
--_adjusted-block-skew: 0deg;
LowToken bypass

U2Scrollbar track color hardcoded, bypassing the design tokens

general.css:351
Issue
::-webkit-scrollbar-track { background:#eee } is a stray neutral (the thumb directly above correctly uses var(--main-color)). #eee maps to no token and doesn't match --page-bg-color (#f7fafb). Cosmetic, no layout impact.
Screens
desktop scrollbars
Fix
Introduce --scrollbar-track-color in :root and reference it, or use var(--page-bg-color).
LowFootgun

U3Global horizontal-scroll guard has a false, footgun-inviting comment

general.css:1605
Issue
The comment states “no position:sticky in use, so this is safe” — but .subpage-header (subpage.css:17) and .pub-meta-card (publication-item.css:128) both use position:sticky. The layout works only because the author used overflow-x: clip (not hidden). A future “equivalent” swap to hidden — which the comment's reasoning invites — would make html/body a scroll container and break both sticky headers site-wide.
Screens
all widths
Fix
Keep clip; rewrite the comment to lock in the requirement (“MUST stay clip, NOT hidden — sticky elements depend on it”).

🚀 Accessibility & Quick Wins

Easy refactors that materially improve usability: keyboard access, screen-reader semantics, and mobile touch-target sizing.

High

A1Video year-filter is completely keyboard-inaccessible

general.css:992 · videos.html:18
Issue
The year filter is a native <input type=checkbox> set to display:none, which removes it from both the tab order and the accessibility tree; the wrapping <label> isn't focusable and no JS restores keyboard handling. Keyboard / switch / AT users cannot toggle the filters at all (WCAG 2.1.1), and there is no focus indicator. The same pattern is reused on the Members and Group-Life filters.
Screens
all widths
Fix
Visually hide instead of removing, and add a focus ring on the label: 
.filter-checkbox {
  position:absolute; width:1px; height:1px; margin:-1px;
  overflow:hidden; clip-path:inset(50%); border:0;
}
.filter-checkbox:focus-visible + .filter-label {
  outline:0.125rem solid var(--main-color-2); outline-offset:0.25rem;
}
Medium

A2Mobile menu uses invalid <ui> elements instead of <li>

menu.html:13, 19, 28
Issue
The nav drawer is a <ul> whose children are non-standard <ui> tags, so it loses list semantics (no “list, N items” announcement). The CSS even carries a hack at general.css:1651 to force-block these unknown elements — the author's comment admits it's “cheaper than fixing the template.”
Screens
all widths
Fix
Rename each <ui>→<li> (and closing tags). .menu-wrapper is display:flex, which blockifies the items, so the CSS hack becomes redundant and can be dropped. No visual change.
Medium

A3Burger button never exposes its open / closed state

menu.html:1 · general.js:56, 73
Issue
The disclosure button has a static aria-label="Open menu" and no aria-expanded / aria-controls; menuOpen()/menuClose() toggle only classes. Screen readers announce “Open menu” even while the panel is open (WCAG 4.1.2).
Screens
all widths
Fix
Add aria-expanded="false" aria-controls="site-menu" to the button, id="site-menu" to the <nav>, and menuBtn.setAttribute('aria-expanded', …) in the two toggle functions.
Medium

A4Full-screen menu overlay — no Esc key, no focus trap, no focus management

general.js:85
Issue
Handlers bind click only. Opening the overlay doesn't move focus into the drawer, focus isn't trapped, the underlying page stays tabbable behind the z-index:999 overlay, and Escape doesn't dismiss it (WCAG 2.4.3).
Screens
all widths (worst for desktop keyboard users)
Fix
In menuOpen() call menuCloseBtn.focus(); in menuClose() return focus to menuBtn; add a global keydown Escape → menuClose() and a Tab-cycle trap; optionally role="dialog" aria-modal="true" on the <nav> and inert the page shell while open.
Medium

A5News category badges (Honors / Events / Outreach) fail color-contrast

subpage.css:735
Issue
The pills render saturated brand-color text on a ~13–22% tint of the same hue → measured ~2.2–2.6:1, well below the 4.5:1 AA minimum for this small (10–10.5px) uppercase text.
Screens
all widths
Fix
Darken each text token and deepen the fill until ≥4.5:1, e.g. color: color-mix(in srgb, var(--main-color-2) 45%, #000) on a 20% fill (reaches ~7:1). Verify each pair with a contrast checker.
Medium+ Low

✅ Checked & Found Solid

Verified against the client's priority list — these behave correctly and need no change.

  • Publication long titles / author lists / DOIs wrap correctly (global overflow-wrap:break-word + word-break:break-all on identifiers). No overflow.
  • Contact inputs are width:100% with border-box — they fit a 320px viewport (only the skew glitch, U1).
  • Members grid alignment is robust across short-EN / long-EN / Chinese name lengths — no squeezed columns.
  • Mobile menu causes no horizontal overflow or page shift; the global overflow-x:clip guard neutralizes stray overflows site-wide.
  • Typography scales via per-breakpoint :root font-size + token overrides; no fixed px widths trigger horizontal scroll.

Rejected False Positives

Four candidates were dropped during adversarial verification — recorded for transparency.

Member .res-tag “overflow” (member.css:278)

Verdict
Inert text-overflow:ellipsis (no overflow:hidden), but the longest real tag (“Environmental Protection”) fits the ~264px mobile column and flex min-content flooring prevents overflow. Latent code smell, not a live breakage. (Raised twice — both instances rejected.)

Project partner-logo row overflow (project-item.css:482)

Verdict
The only wide wordmark (nextdrive, ~105px) fits the mobile row; and any residual overflow is clipped by the global overflow-x:clip guard — no page-level horizontal scroll occurs.

Project output-link raw-URL overflow (project-item.css:250)

Verdict
Guarded by overflow-x:clip, and the code path is never exercised — all current outputs use a title, never a raw URL as link text.
